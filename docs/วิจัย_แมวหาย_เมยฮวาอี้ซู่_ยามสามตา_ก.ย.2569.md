## 1. 梅花易数 — สิ่งที่ verify แล้ว

### 1.1 สูตรตั้งกัวจากเวลา (年月日時起卦) — ต้นฉบับ 卷一 คำต่อคำ
> 「年月日為上卦。年月日加時總數為下卦。又以年月日時總數取爻。如子年一數…亥年十二數。月如正月一數…
> 日數如初一一數…三十數。以八除之，以餘數作卦。…以六除，餘數作動爻。」

- ปี = เลข地支 (子1 … 亥12) · เดือน = เลขเดือน**จันทรคติจีน** · วัน = วันจันทรคติ (初一=1…30) · ชั่วโมง = 时辰 (子1 … 亥12, ช่วงละ 2 ชม.)
- กัวบน = (ปี+เดือน+วัน) mod 8 · กัวล่าง = (ปี+เดือน+วัน+ชม.) mod 8 · เส้นเคลื่อน = ผลรวมทั้งสี่ mod 6 (เศษ 0 → 8 / 6)
- ลำดับ 1-8 = 乾 兌 離 震 巽 坎 艮 坤 · กัวที่มีเส้นเคลื่อน = 用 (สิ่งที่ถาม/ของหาย) อีกกัว = 體 (ผู้ถาม) · 變卦 = พลิกเส้นเคลื่อน
- ✅ cross-check: sohu (梅花易数 起卦方法) + สรุปหลายเว็บใน search ตรงกัน 100% รวมตัวอย่างเลข (辰年5+12月+17日=34→兌 …)

### 1.2 ตารางทิศ + ภูมิประเทศ 8 กัว (八卦萬物屬類 卷一 — ต้นฉบับ)

| กัว | ทิศ (後天) | 地理/處所 ต้นฉบับ | ถอดเป็นภาษาค้นแมว |
|---|---|---|---|
| 乾 | ตะวันตกเฉียงเหนือ | 京都、大郡、形勝之地、高亢之所 | ที่สูง ดาดฟ้า ตึกใหญ่ สถานที่ราชการ |
| 兌 | ตะวันตก | 澤、水際、缺池、廢井、山崩破裂之地 | ที่ลุ่ม ริมน้ำ บ่อร้าง ที่พังทลาย/ซอกแตก |
| 離 | ใต้ | 幹亢之地、窖灶、爐冶之所 | ที่แห้งร้อน ครัว เตา ใกล้ไฟ |
| 震 | ตะวันออก | 樹木、鬧市、大途、竹林、草木茂盛之所 | ต้นไม้ใหญ่ ถนนใหญ่ ตลาด ที่พลุกพล่าน |
| 巽 | ตะวันออกเฉียงใต้ | 草木茂秀之所、花果菜園 | สวน พุ่มไม้ แปลงผัก ที่ลมโกรก |
| 坎 | เหนือ | 江湖、溪澗、泉井、卑濕之地 | ร่องน้ำ ท่อ ที่ชื้น ใต้ถุนเปียก |
| 艮 | ตะวันออกเฉียงเหนือ | 山徑路、近山城、丘陵、墳墓 | ทางเดินแคบ เนิน กำแพง มุมตึก กองหิน/ของนิ่งๆ |
| 坤 | ตะวันตกเฉียงใต้ | 田野、鄉裏、平地 | ทุ่ง ลานดิน ที่ราบ บ้านคนใจดี |

→ ตรงกับตารางในเอกสาร B ทุกทิศ (เอกสาร B ถอดจากตำราเดียวกัน) — ถือว่า verify กับต้นฉบับแล้ว

### 1.3 กฎ失物占 (卷二 體用總訣 — ต้นฉบับ)
- 體 = ผู้ถาม · 用 = ของที่หาย · **「以變卦為失物之所在」 — ทิศ/สถานที่อ่านจาก變卦** (บางสำนักดู 用卦 ประกอบ — ประกาศธรรมเนียม)
- 體克用 = 可尋遲得 (หาได้แต่ช้า) · 用生體 = 物易尋 (หาง่าย) · 比和 = 物不失 (ไม่หายจริง/ได้คืนง่าย) · 體生用 = 物難見 (หายาก) · 用克體 = **不可尋 (หาไม่ได้)**
- ⚠️ 用克體 → ระบบ**ห้ามพูดว่า "หาไม่ได้"** (กติกาแมวหาย: ห้ามฟันธง/ห้ามบอกเลิกค้น) → แปลงเป็น "ตำราว่าค้นยาก — ขยายวงและใช้เครือข่ายช่วย" เท่านั้น · 體用 มีผลกับ**ตัวคูณวงระยะเบาๆ** (เอกสาร B เสนอ 0.8-1.2) ไม่ใช่ตัดสินได้คืนหรือไม่

### 1.4 สิ่งที่ต้องสร้างก่อนเขียนชั้นนี้ (ไม่มีในระบบ)
1. **ปฏิทินจันทรคติจีน** (定朔法): เดือน/วันจันทรคติ + เดือนอธิกมาส — ระบบมีเครื่องมือดาราศาสตร์ครบ (`solarEclipticLongitude` verify แล้ว · `moonEclipticLongitude` Meeus ~ลิปดา · ลี่ชุนมีแล้ว) → คำนวณจุดจันทร์ดับ (จันทร์−อาทิตย์ = 0°) + 中氣ทั้ง 12 → เดือนที่ไม่มี中氣 = อธิกมาส · ปีปฏิทินเริ่มเดือนที่มี 雨水 · **ต้อง verify** กับตารางวันตรุษจีน (มีจาก Wikipedia: 2026-02-17 · 2027-02-06 · 2028-01-26 · 2029-02-13 · 2030-02-03 · 2031-01-23 · 2032-02-11 · 2033-01-31 · 2034-02-19 · 2035-02-08) + ปีอธิกมาส (ต้องหาแหล่ง HKO/中國天文年曆)
2. 时辰: 子 23:00-01:00 … (子時ข้ามวันหรือไม่ — สำนักต่างกัน ต้องเลือกและประกาศ) · เลขปีใช้ 地支 ตามปีจันทรคติ (บางสำนักใช้ 立春) — ประกาศ
3. เอนจิน: ตั้งกัว → 體/用/變 → ทิศจาก變卦 (+用卦 รอง) · ภูมิประเทศ → environment_hint · 體用 → ตัวคูณระยะ + recovery_omen (กรองถ้อยคำ) · เทสต์: ตัวอย่างตัวเลขจากตำรา (34→兌, 43→離, 43 mod 6=1 初爻動 → 澤山咸)
4. เสียบเข้า `lostCatPlan` เป็นชั้น T น้ำหนักต่ำ (เอกสาร B เสนอ 0.6 ของชั้น T — ผมเสนอเริ่มต่ำกว่า แล้วให้ calibration loop ปรับตามจริง) · **ถ้าชั้นนี้ไม่ต่างจากสุ่มใน hit-rate ต้องลดน้ำหนักลง** — ซื่อสัตย์กับหลัก "คำนวณจริง"

### 1.5 ประมาณการ
ปฏิทินจันทรคติ+verify ≈ ครึ่งวัน · เอนจินกัว+เทสต์ ≈ ครึ่งวัน · wiring+UI (ช่องเวลาที่หาย) ≈ สั้น · ต้นทุนรัน ฿0 (คำนวณล้วน)

## 2. ยามสามตา — สิ่งที่พบ

- **มีต้นฉบับเปิด** (thaiboraan ถอดตำรา + ศิลปวัฒนธรรม): สามตำแหน่งวนกัน อาทิตย์(ใส) จันทร์(ปลอด) อังคาร(ดำ) · ข้างขึ้นนับตามเข็ม 1-2-3 · ข้างแรมนับทวน 1-3-2 · นับตามวันขึ้น/แรมกี่ค่ำจนถึงวันที่ถาม แล้วนับยามต่อ (กลางวัน/กลางคืนอย่างละ 8 ยาม ยามละ 1.5 ชม. เริ่ม 06:00) → ตกช่องใด
- คำทำนายเรื่องของหาย/สัตว์หาย (ต้นฉบับ): เศษ ๑ = คนในเรือนเอาไปซ่อน · เศษ ๒ = ซ่อน**ทางเหนือและใต้** มีผู้นำคืน · เศษ ๓ = อยู่**ทิศตะวันออก-ตะวันตก** จะได้คืน · สัตว์หาย: ดำ=ได้ · ใส=ได้เมื่อเวลาผ่านไป · **ปลอด=ไม่ได้** · (เจ็บป่วย: ดำ=ตาย …)
- ⚠️ ปัญหา 3 ข้อ: (1) ทิศเป็น "แกน" สองทิศตรงข้ามกัน ไม่ช่วยจัดลำดับ 8 ทิศ (2) มีคำทำนายชี้ขาด "ไม่ได้/ตาย" ชนกติกาแมวหายและ safety tone ตรงๆ (3) การจับคู่ เศษ 1/2/3 ↔ ใส/ปลอด/ดำ ระหว่างสองแหล่งยังไม่ชัดว่าตรงกันอย่างไร
- **ข้อเสนอ: ไม่ใส่เป็นชั้นคะแนน** — ถ้าอยากมี "กลิ่นตำราไทย" ใช้ได้แค่บรรทัดภาษาตำราที่กรองแล้ว (เช่น "ตำรายามสามตาชี้แกนเหนือ-ใต้") น้ำหนัก 0 ต่อการจัดลำดับ

## 3. คำแนะนำสำหรับการตัดสินใจ
1. **梅花易数 → ทำเป็นรอบ implement แยก** (สูตร+ตาราง+กฎ verify กับต้นฉบับครบ · ต้องสร้างปฏิทินจันทรคติจีนก่อน) ใส่เป็นชั้นเสริมน้ำหนักต่ำ + กรองถ้อยคำ "ไม่พบ" + ให้ calibration loop ตัดสินน้ำหนักจริง
2. **ยามสามตา → ไม่ทำเป็นชั้นคะแนน** (เหตุผลข้อ 2)
3. ระหว่างรอ: เก็บผล "เจอแล้ว" จากเฟส 1 ให้ได้สัก 30-50 เคสก่อน จะได้มี baseline วัดว่าชั้นตำราช่วยจริงไหม
