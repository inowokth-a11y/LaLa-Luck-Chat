# ร่างความยินยอมการใช้ข้อมูลชีวมิติ (face-card) — รอผู้ใช้/ผู้รู้กฎหมายรีวิว

> ⚠️ **สถานะ: ร่าง (21 ส.ค. 2569)** — ยังไม่ผ่านการตรวจโดยผู้รู้กฎหมาย PDPA
> ข้อความที่ใช้จริงบนหน้าเว็บอยู่ที่ `lib/face-card/consent.ts` (FACE_CONSENT_VERSION 2026-08-21.1)
> **แก้เอกสารนี้เมื่อไหร่ ต้องแก้ consent.ts ให้ตรงกัน + ขยับเวอร์ชันเสมอ**

## บริบท

ฟีเจอร์ "ภาพฉันในบทบาทการ์ด" (face-card) ให้ผู้ใช้อัปโหลดรูปถ่ายใบหน้า แล้วระบบสร้างภาพศิลปะ
สไตล์คิวบิสม์ของผู้ใช้ในบทบาทตัวละครประจำการ์ดพลังงาน — **รูปถ่ายใบหน้าเป็นข้อมูลชีวมิติ
ซึ่งเป็นข้อมูลส่วนบุคคลอ่อนไหวตาม PDPA มาตรา 26** ต้องได้ความยินยอมโดยชัดแจ้ง (explicit
consent) ก่อนเก็บรวบรวม/ใช้/เปิดเผย

## สาระของความยินยอม (ตามที่ implement จริง)

| หัวข้อ | รายละเอียด |
|---|---|
| ข้อมูลที่ประมวลผล | รูปถ่ายใบหน้าที่ผู้ใช้อัปโหลด (ย่อฝั่งเบราว์เซอร์ ≤1024px — การ re-encode ล้าง EXIF/GPS ออกก่อนส่ง) |
| วัตถุประสงค์ | สร้างภาพศิลปะ "ผู้ใช้ในบทบาทการ์ดพลังงาน" เพียงวัตถุประสงค์เดียว |
| ผู้ประมวลผลภายนอก | fal.ai (สร้างภาพ FLUX PuLID) · Anthropic Claude (ตรวจว่าเป็นรูปใบหน้าเดี่ยวที่ชัด) — ส่งแบบครั้งต่อครั้ง |
| การจัดเก็บรูปต้นฉบับ | **ไม่จัดเก็บ** — อยู่ในหน่วยความจำระหว่างประมวลผลแล้วทิ้ง (ระบบ log เก็บเพียง hash ย่อไว้ตามรอยการใช้งาน ไม่สามารถย้อนเป็นรูปได้) |
| สิ่งที่จัดเก็บถาวร | เฉพาะภาพผลงานศิลปะที่สร้างเสร็จ ในพื้นที่เก็บข้อมูลส่วนตัว (private bucket — ไม่มี URL สาธารณะ) |
| การเผยแพร่ | เกิดขึ้นเฉพาะเมื่อผู้ใช้กดแชร์ลิงก์ `/s/<token>` ของตนเอง (token สุ่ม เดาไม่ได้) — หน้าแชร์มีเฉพาะภาพผลงาน + ข้อมูลการ์ดสาธารณะ ไม่มีชื่อ/ข้อมูลส่วนตัว |
| ระยะเวลาเก็บ | จนกว่าผู้ใช้ลบบัญชี — การลบบัญชีลบทั้งแถวข้อมูลและไฟล์ภาพใน Storage (implement แล้วใน /api/account/delete) |
| การถอนความยินยอม | ลบบัญชี = ถอนความยินยอมโดยสมบูรณ์ · การไม่ให้ความยินยอมไม่กระทบบริการส่วนอื่น |
| การใช้เทรนโมเดล | ไม่ใช้ข้อมูลผู้ใช้เทรนโมเดล AI |

## จุดที่ควรให้ผู้รู้กฎหมายตรวจเป็นพิเศษ

1. **fal.ai เป็นผู้ประมวลผลต่างประเทศ** — การส่งข้อมูลชีวมิติออกนอกประเทศต้องมีมาตรการตาม
   PDPA มาตรา 28-29 (fal มี privacy policy/DPA หรือไม่ ควรตรวจก่อนเปิดเชิงพาณิชย์)
2. อายุผู้ใช้ — ระบบยังไม่ตรวจอายุ ถ้าผู้เยาว์ใช้ฟีเจอร์นี้ ความยินยอมต้องมาจากผู้ปกครอง (ม.20)
3. ควรเพิ่มข้อความนี้เข้า `/privacy` (นโยบายความเป็นส่วนตัวหลัก) และขยับ PDPA_VERSION
   เมื่อเปิดใช้จริงเชิงพาณิชย์ — ตอนนี้ consent แยกจุด (ติ๊กก่อนอัปโหลดทุกครั้ง) ครอบอยู่แล้ว
4. ถ้อยคำ "ภาพผลงาน" — ภาพที่สไตล์แปลงแล้วยังอาจระบุตัวบุคคลได้ (ใบหน้าจดจำได้) จึงยังนับเป็น
   ข้อมูลส่วนบุคคล — สิทธิ์ลบ/เข้าถึงต้องใช้ได้กับภาพผลงานด้วย (ระบบรองรับผ่านการลบบัญชี)
